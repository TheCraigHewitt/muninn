# Bruh v0: the local version

v0 is the smallest Bruh that's useful: one person, on one laptop, pointing Bruh at conversations they already have. It proves the core loop (conversation → cited Memory → answer) before any of the hosted, multi-user machinery in [`TECH_SPEC.md`](TECH_SPEC.md).

## What it does

1. **Reads** meeting transcripts (`.txt`) and Slack export folders, a folder of transcripts as new ones land (`bruh watch`), and Slack channels live through a bot (`bruh slack`, see [`SLACK.md`](SLACK.md)).
2. **Extracts** Memories: Decisions, Proposals, Rationales, Commitments, Facts and open Questions. Each one cites the exact words it came from, and the words are checked to be verbatim. Jokes, hypotheticals and quotes of other people are labelled and never used as evidence.
3. **Reconciles** each new Memory with what Bruh already knows: a repeat adds evidence to the existing Memory, a reversal supersedes it, a conflict is linked, and everything is filed under a shared Topic.
4. **Answers** questions in plain language, citing Memories, and tells a changed position as a timeline.
5. **Asks for help** when unsure: Decisions and reversals below the confidence bar wait in a Review Queue for a person to confirm.

## How it differs from the spec

| Spec | v0 | Why |
|---|---|---|
| PostgreSQL + pgvector, Redis workers | One SQLite file in `data/` | Nothing to install or run |
| Live Slack connector, one Source per message | A Socket Mode bot; each quiet stretch of a channel is one Source, split by week | No public URL needed; whole discussions read better than single messages |
| Google Meet and Calendar connectors | A watched folder of transcripts | Works with any meeting-notes app's export today, no Google app review |
| Sign in with Slack, Access Scopes per Memory | One audience: whoever can ask, sees all | Fine for a small team that only feeds Bruh what everyone could see |
| Edits withdraw Evidence (ADR-0003) | Deletes erase; edits are followed only before Bruh reads the message | The privacy-critical half first |
| Hybrid vector + keyword retrieval | The whole memory, or a word-overlap shortlist, goes to the model | Fine up to a few thousand Memories |
| MCP server, Agent Reports | Not yet | Later milestones |

The domain language in [`CONTEXT.md`](../CONTEXT.md) and the decisions in [`adr/`](adr/) still hold. v0 implements a subset of them.

## Extraction rules learned from real data

A prototype run on a month of a real team's meetings and Slack (kept private) set these rules:

- **Durable memory only.** Status updates ("the PR is merged"), schedules and small talk are not Memories.
- **A retold decision is not a new decision.** "As you know, we stopped X" adds evidence to the existing Memory, or is recorded once and marked as decided earlier.
- **Supersedes replaces a recorded position of the same type.** A proposal turned down before it was decided isn't superseded; it just never becomes a Decision.
- **Unknown speakers can't decide or own.** Transcripts that can't tell who spoke ("Them") can support facts and questions, but a Decision resting only on them goes to review and a Commitment gets no owner.
- **Bots never decide or commit,** and channels that are almost entirely bot posts are skipped.

## Models

Extraction defaults to Claude Opus (`BRUH_MODEL` overrides it). In the prototype, Sonnet matched Opus on headline decisions but missed most reversals and reasons; Haiku missed more. Responses are cached on disk, so re-running an ingest or an eval doesn't call the model again, and `bruh spend` shows usage.
